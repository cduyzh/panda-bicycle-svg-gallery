# 🐼 熊猫骑行实验室 | AI 大模型生成 SVG 动画能力对比 (LLM PK)

这是一个本地 SVG 动画画廊，旨在记录和对比不同 AI 大模型（LLM）的 SVG 矢量图形与动画生成能力。本项目通过一道统一的测试题——“画一个熊猫骑自行车的 SVG 动画”，直观展示 **OpenAI GPT、Anthropic Claude、Google Gemini** 等海外顶尖大模型，与 **DeepSeek、Qwen (通义千问)、GLM (智谱)、MiniMax、Kimi (月之暗面)、Step (阶跃星辰)、Seed** 等国产大模型之间的生成能力 PK 表现。

无论您是在关注“国产大模型对比”、“Claude vs OpenAI”，还是想了解最强代码生成大模型的最新进展，都可以通过本画廊获得最直观的视觉参考！

## ✨ 项目特色

- **主流模型同台 PK**：涵盖了市面上主流的海外大模型（Claude 3.5 Sonnet/Opus, GPT, Gemini）与国产大模型（DeepSeek, Qwen, GLM 等）。
- **结构化对比展示**：页面按“模型系列 → 具体型号 → 生成配置 → 生成记录”自动归类整理：每个型号只占一张卡片，在预览面板中无缝切换不同模型的生成结果，方便细致对比。
- **友好的交互体验**：支持快速搜索、模型系列筛选、排序（最新更新/模型名称/作品数量），并支持键盘左右键快速切换查看作品。
- **保留模型原始输出**：原 SVG 文件名与生成配置完整保留，页面日期来自文件修改时间，绝不干预或粉饰模型的原始生成结果。
- **逐作品评分**：卡片展示最新一份作品的总分、档位与一句话点评，预览内可切换作品并查看四维、13 小项和评分依据；支持按最新作品分数排序。
- **公开制度**：满分 100，形象 30%、动画 35%、视觉 20%、技术 15%。页面公开小项标准、总分档位、来源与检查范围，并提供原评分表下载。

## 🚀 运行方法

1. 启动本地 Python 服务器：
```bash
python3 server.py
```
2. 然后在浏览器访问 `http://localhost:8000`。

## 💡 如何添加新模型的生成记录？

把新的 SVG 文件放进本目录即可自动出现在画廊，无须修改页面代码。
系统会根据文件名自动识别模型与配置，原文件名会完整保留。
* 例如 `6 Luna Max.svg` 和 `6 Luna Max2.svg` 会归到同一型号、同一配置下；末尾的 `2` 表示再次生成。
* `0731`、`0813` 等型号修订编号仍属于型号本身。
* 页面上的日期读取自文件修改时间。

## 评分数据与计算

`scoring.json` 是页面评分的唯一数据源，含规则、档位与每个原始文件名对应的评审。现有 38 份作品中，15 份沿用 Excel 原表的 13 项分数，23 份由 Codex 按相同标准补评。原表中的下划线、版本号和文件别名通过显式映射及字节数核对；原表文件不改写。原始点评保存于 `originalComment`，页面点评做必要精简。

四维满分为 30 / 35 / 20 / 15，小项直接相加就是总分，不能再重复乘权重。若另外做权重模拟，公式是 `Σ（维度得分 / 维度满分 × 新权重）`，新权重合计应为 100；模拟结果不替换正式评分。

档位：90–100 惊艳；80 至不足 90 优秀；70 至不足 80 良好；60 至不足 70 及格；不足 60 有明显缺陷。分数允许为 0，未评分与 0 分分别显示。

评分针对单份输出，约有 ±3 分主观误差，接近分数按同一梯队理解。原表只看 0–2 秒 12 帧；本次补评检查 XML/源码以及 0、0.12、0.36、0.6、1、1.5、2、6、12、30、30.12 秒截图。离散取样不能证明连续动画流畅或所有长循环无接缝，未测 Safari、移动浏览器及真机帧率。

服务端 `/api/svgs` 自动关联每份评分，`/api/scoring` 公开规则。页面每 15 秒刷新；新增 SVG 先显示「待评分」，内容 SHA-256 或规则版本变化时显示「待复评」，完成下列流程后展示新分数。

## 新增或修改 SVG 的评分流程

1. 把原 SVG 放进根目录，保持文件名，运行 `python3 scoring.py audit`。命令输出未评、待复评和已删除作品的旧记录；未全部处理时返回非零。
2. 生成本轮评审和截图计划（`--out` 使用新的 `work/` 子目录，避免覆盖已有评审）：

   ```bash
   python3 scoring.py prepare --out work/scoring-next
   node /Users/hobby/.codex/tools/browser-qa/capture.mjs work/scoring-next/capture-plan.json
   ```

   默认只处理缺评与待复评作品；可用 `--files '文件名.svg'` 指定复核对象。截图按 SVG 的原始画布尺寸，同一作品的时间点复用同一页面，全部作品共用一个浏览器。技术检查及待填分数在 `work/scoring-next/review.json`，截图在该目录 `frames/`。
3. 实际查看各时间点画面，结合源码检查熊猫辨识、车架、手握车把、身体坐稳、腿脚与曲柄联动，以及次级动作、视差和首帧异常。必要时补充围绕真实动画周期的取样，同步修改截图计划与 `sampleTimesMs`；若做连续播放，另记实际检查方法和范围。
4. 填写评审 JSON：`scores` 的全部 13 个小项、`comment` 的一句话点评、`notes` 的四维评分依据、实际 `reviewer` 和 `reviewedAt`。原表同梯队作品用于校准；同画面同实现用一致标准，优缺点扣到对应小项，不根据模型名、文件体积或动作数量推分。技术测量是辅助证据，审美和动作是否合理需要评审者判断。
5. 更新并校验：

   ```bash
   python3 scoring.py apply work/scoring-next/review.json
   python3 scoring.py audit
   python3 -m unittest discover -s tests
   ```

   `apply` 校验小项范围、四维依据、截图存在、文件内容和规则版本，全部通过后原子更新数据；总分、维度分及档位实时计算，不手写重复总分。评审失败不会覆盖已有数据。
6. 查看页面分数与预览作品是否对应，切换生成记录核对数据；涉及页面改动时运行 `node tests/scoring-ui.mjs`，该测试会自行启动并清理临时本地服务与受管浏览器。

这套流程也写入 `AGENTS.md`，后续 agent 新增或修改 SVG 时须在同一任务内补评并更新。服务器负责收录、识别改动与展示状态；它不会在后台自动判断画面或编造评分。修改正式规则需升级 `rubricVersion` 并复评受影响作品。
